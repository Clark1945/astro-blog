## 前言

上週的文章中我們提到了如何在Cloudflare上面買domain，這次我預計說明Domain Name是如何一步步訪問到我們架起的服務的，那麼我們開始吧。

首先，以我們當前的blog舉例：https://blog.clarkliu.com。在實際訪問到伺服器主機前，會經過以下步驟。

1. 瀏覽器查本機快取（無結果）

2. 瀏覽器詢問**Recursive Resolver**（ISP 或 8.8.8.8）
   **Recursive Resolver**主要替你負責不斷地輪詢主機，最後幫你把你要的答案，也就是IP位址抓回來，預設主機的Recursive Resolver會是來自ISP提供的服務，例如說中華電信、遠傳等等。
3. **Recursive Resolver** 詢問 **Root Name Server** → 得到 TLD NS 的 IP。
   **Top Level Domain Name Server**主要負責保存相關Top Level網域的資訊，比方說".com"就是一個Top Level Domain，除此之外常見的TLD NS包含"jp"、"tw"等等。
4. **Recursive Resolver** 詢問 **TLD Name Server** → 得到 **Authoritative NS** 的 IP
   **Authoritative NS**是雲端服務商的**Domain Name Server**，這裡保存著用戶Domain Name所對應的IP，如果你使用AWS去管理DNS 就會是 AWS Route 53，你如果是Cloudflare 就會是 Cloudflare的服務等等。
5. Recursive Resolver 詢問 **Authoritative Name Server** → 得到最終 IP
6. 結果回傳瀏覽器，並快取起來

以上的範例是 若從Cloudflare購買網域，且DNS也透過Cloudflare管理的情況，但如果你只是透過cloudflare買domain，實際上是使用AWS Route 53管理DNS的話，狀況就更複雜了。

DNS中可以設定多種Type，最常見的就是A與CNAME了，這邊我使用AI一次列出各種DNS Type。

| Record Type | 功能                  | 範例                              | 補充                          |
| ----------- | --------------------- | --------------------------------- | ----------------------------- |
| A           | 網域 → IPv4           | `yoursite.com -> 104.21.1.1`      | 最常見                        |
| AAAA        | 網域 → IPv6           | `yoursite.com -> 2606:4700::...`  | IPv6 版本的 A Record          |
| CNAME       | 網域別名 → 另一個網域 | `www -> yoursite.com`             | 不能直接指向 IP               |
| MX          | 郵件伺服器            | `yoursite.com -> mail.google.com` | Email 收信用                  |
| TXT         | 純文字資訊            | SPF / DKIM / 網域驗證             | 很多 SaaS 都靠它驗證          |
| NS          | 指定 DNS 管理者       | `ns1.cloudflare.com`              | 告訴全世界「去哪查這個網域」  |
| SOA         | DNS Zone 的管理資訊   | serial、refresh 等                | DNS 同步機制重要依據          |
| SRV         | 服務位置資訊          | `_sip._tcp.example.com`           | 常見於 SIP、Minecraft、K8s 等 |

透過以上描述，你應該可以很清楚的知道DNS背後的運作可能相當複雜，而每一次的請求如果都需要這樣訪問，那速度可想而知將會非常慢，於是為了減少DNS解析需要消耗的時間，我們透過多層快取來提升系統運作的效能。當中包含

- Recursive Resolver 快取 → 最重要，TTL 到期前不會再問 Authoritative
- OS 快取 → TTL 到期或重啟清除
- 瀏覽器快取 → TTL 到期或關閉瀏覽器清除
