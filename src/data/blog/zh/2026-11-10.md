## 前端框架Note

Vue、Vite、Pinia、Nuxt 常被一起提起，但它們是不同層級的東西。先分清楚，後面才不會混。

| 名稱           | 角色                  | 一句話                                                              |
| -------------- | --------------------- | ------------------------------------------------------------------- |
| **Vue 3**      | UI 框架（核心）       | 用響應式資料驅動畫面：資料變，畫面自動更新                          |
| **Vite**       | 開發伺服器 + 建置工具 | 開發時用瀏覽器原生 ES Module，秒開、熱更新；正式建置時打包          |
| **Vue Router** | 官方路由              | 網址對應到元件，SPA 必備                                            |
| **Pinia**      | 官方狀態管理          | 跨元件共享狀態，取代 Vuex                                           |
| **Nuxt 3**     | 全端 meta-framework   | Vue + Vite + Router + Nitro 伺服器 + 檔案式路由 + SSR，全部預先組好 |

### Vue

網頁渲染模式

| 模式      | HTML 在哪裡產生            | 優點                             | 缺點                                |
| --------- | -------------------------- | -------------------------------- | ----------------------------------- |
| CSR / SPA | 瀏覽器，執行 JS 後才有內容 | 部署簡單（純靜態檔）、頁面切換順 | 首屏慢、SEO 與社群預覽差            |
| SSR       | 每次請求，在伺服器上       | 首屏快、SEO 好、資料新           | 需要 Node 伺服器、有 hydration 的坑 |

- ==開發時==：不先打包。瀏覽器請求哪個模組，Vite 就即時轉換（TS、`.vue`、JSX）並回傳，利用瀏覽器原生 `<script type="module">`。第三方套件用 esbuild 預先打包一次（pre-bundling），因為很多套件是 CJS，或由上百個小檔案組成，直接丟給瀏覽器會很慢。
- ==熱更新（HMR）==：改一個檔案，只替換該模組，並保留其餘狀態。`.vue` 檔的 HMR 由外掛處理。
- ==正式建置==：`vite build` 用 Rollup（新版本在逐步換成 Rolldown，用法不變）打包，做 tree-shaking、程式碼分割、雜湊檔名。
- 前端的環境變數是在**建置時**寫死進 bundle，任何人都能在瀏覽器看到。API 金鑰、資料庫密碼絕對不能放 VITE\_ 變數。需要機密就放在伺服器端（Nuxt 的 server routes，或你的後端）。

```javascript
import { fileURLToPath, URL } from "node:url";
import { defineConfig } from "vite";
import vue from "@vitejs/plugin-vue";

export default defineConfig({
  plugins: [vue()],
  resolve: {
    alias: { "@": fileURLToPath(new URL("./src", import.meta.url)) },
  },
  server: {
    port: 5173,
    proxy: {
      // 開發時把 /api 轉給後端，避免 CORS
      "/api": { target: "http://localhost:8080", changeOrigin: true },
    },
  },
  build: {
    sourcemap: true,
    rollupOptions: {
      output: {
        manualChunks: { vendor: ["vue", "vue-router", "pinia"] },
      },
    },
  },
});
```

一個 .vue 檔把一個元件的模板、邏輯、樣式放在一起。現在的標準寫法是 ==`<script setup>`==：頂層宣告的變數與函式會自動暴露給模板，不用再 `return`。

```vue
<script setup lang="ts">
import { ref } from "vue";

const count = ref(0);
function inc() {
  count.value++;
}
</script>

<template>
  <button class="btn" @click="inc">點了 {{ count }} 次</button>
</template>

<style scoped>
.btn {
  padding: 4px 12px;
}
</style>
```

#### 模板指令速查

| 語法                                  | 用途               | 備註                                                       |
| ------------------------------------- | ------------------ | ---------------------------------------------------------- |
| `{{ expr }}`                          | 文字插值           | 只能放**單一表達式**，不能放陳述式（if、for）              |
| `:attr="expr"`                        | 綁定屬性（v-bind） | 屬性名與變數同名時可寫 `:id`（3.4+）                       |
| `@click="fn"`                         | 監聽事件（v-on）   | 修飾符 `.prevent` `.stop` `.once` `.enter`                 |
| `v-if / v-else-if / v-else`           | 條件渲染           | 真的建立 / 銷毀 DOM 與子元件                               |
| `v-show`                              | 切換 `display`     | 元素一直存在；切換頻繁用它                                 |
| `v-for="item in list" :key="item.id"` | 列表渲染           | `key` 要用穩定且唯一的值                                   |
| `v-model`                             | 雙向綁定           | 是 `:value` + `@input` 的語法糖；`.trim` `.number` `.lazy` |

#### class 與 style 綁定

```vue
<div
  :class="['card', { active: isActive, 'is-error': hasError }]"
  :style="{ color: textColor, fontSize: size + 'px' }"
></div>
```

#### 為什麼 key 很重要

Vue 更新列表時，用 key 判斷「哪個節點是原來那個」。沒有 key 或用 index 當 key，在列表會插入、刪除、排序時，Vue 會就地重用 DOM，造成輸入框的內容、元件內部狀態錯位到別的資料列上。

```vue
<!-- 錯：刪除第一筆後，第二筆資料會「繼承」第一筆的輸入框內容 -->
<li v-for="(todo, i) in todos" :key="i"><input v-model="draft[i]" /></li>

<!-- 對：使用資料本身的唯一 id -->
<li v-for="todo in todos" :key="todo.id">...</li>
```

#### Vue的響應式系統

Vue 用 Proxy 包住物件。==讀取==屬性時，記錄「目前正在執行的 effect（渲染函式、computed、watch）依賴這個屬性」（track）；==寫入==屬性時，找出依賴它的 effect 重新執行（trigger）。這就是「資料變、畫面自動更新」的全部秘密。

#### ref 與 reactive

```javascript
import { ref, reactive } from "vue";

const count = ref(0); // 任何型別；腳本中要用 .value
count.value++;

const state = reactive({ user: { name: "A" }, list: [] }); // 只能是物件 / 陣列
state.user.name = "B"; // 深層響應
```

#### computed：有快取的衍生值

```javascript
const price = ref(100);
const qty = ref(3);
const total = computed(() => price.value * qty.value); // 只有依賴變動才重算
```

#### watch 與 watchEffect

```javascript
// watch：明確指定來源，拿得到新舊值，預設「惰性」（不會馬上執行）
watch(
  keyword,
  (newV, oldV, onCleanup) => {
    const ctrl = new AbortController();
    onCleanup(() => ctrl.abort()); // 下一次觸發前先取消上一次請求
    fetch(`/api/search?q=${newV}`, { signal: ctrl.signal });
  },
  { immediate: false }
);

// 監聽 reactive 物件的屬性要用 getter
watch(
  () => state.user.name,
  v => {
    /* ... */
  }
);

// 監聽多個來源
watch([a, b], ([newA, newB]) => {
  /* ... */
});

// watchEffect：自動收集依賴，馬上執行一次
watchEffect(() => {
  document.title = `${count.value} 筆`;
});
```

#### 更新是非同步批次的：nextTick

```javascript
count.value++;
console.log(el.value.textContent); // 還是舊的！DOM 尚未更新
await nextTick();
console.log(el.value.textContent); // 新的
```

#### 大型資料與不需深層響應的情況

- `shallowRef` / `shallowReactive`：只追蹤第一層（`.value` 被替換才觸發）。適合上萬筆的大陣列、第三方實例（地圖、圖表物件）。
- `markRaw(obj)`：標記此物件永遠不要被代理。
- `toRaw(proxy)`：取回原始物件，常用在要結構化複製或交給第三方函式庫時。

#### 單向資料流

父元件透過 ==props 往下傳==，子元件透過==事件往上通知==。子元件不要直接修改 props（Vue 會警告）。需要「雙向」時，用 v-model 這個約定。

將變數 u 當作 User interface 傳入 Component 中，觸發 select 事件並呼叫 onSelect 函式。

```vue
<script setup lang="ts">
interface User {
  id: number;
  name: string;
}

const props = withDefaults(
  defineProps<{
    user: User;
    editable?: boolean;
  }>(),
  { editable: false }
);

const emit = defineEmits<{
  (e: "select", id: number): void;
  (e: "rename", id: number, name: string): void;
}>();
</script>

<template>
  <div @click="emit('select', props.user.id)">
    {{ props.user.name }}
  </div>
</template>
```

```vue
<UserCard :user="u" editable @select="onSelect" />
```

#### defineModel：把 v-model 寫成一行（3.4+）

```vue
<script setup lang="ts">
const keyword = defineModel<string>({ default: "" }); // v-model
const page = defineModel<number>("page", { default: 1 }); // v-model:page
</script>

<template>
  <input v-model="keyword" />
</template>
```

#### 插槽（slot）

把外部的 HTML（`<template>...</template>`）插入進去

```vue
<template>
  <table>
    <thead>
      <slot name="header" />
    </thead>
    <tbody>
      <tr v-for="row in rows" :key="row.id">
        <!-- 作用域插槽：把資料交給使用者決定怎麼畫 -->
        <slot name="row" :row="row" :index="row.id">{{ row }}</slot>
      </tr>
    </tbody>
  </table>
</template>
```

```vue
<DataTable :rows="users">
  <template #header><th>姓名</th></template>
  <template #row="{ row }"><td>{{ row.name }}</td></template>
</DataTable>
```

### 什麼時候需要使用 Pinia store

| 狀態的性質                                           | 放哪裡                                                                |
| ---------------------------------------------------- | --------------------------------------------------------------------- |
| 只有一個元件用                                       | 元件內的 ref                                                          |
| 父子之間                                             | props / emit / defineModel                                            |
| 一組相關元件共用（Tabs）                             | provide / inject                                                      |
| 邏輯可重用，但每次呼叫各自獨立                       | composable                                                            |
| 跨頁面、全應用單例（登入者、購物車、權限、偏好設定） | Pinia store                                                           |
| 伺服器資料（列表、詳情）                             | 優先考慮 useFetch / TanStack Query 這類資料快取層，而非手動放進 store |

### Pinia 最小範例

```ts
// stores/cart.ts
import { defineStore } from "pinia";
import { ref, computed } from "vue";

export const useCartStore = defineStore("cart", () => {
  const items = ref<{ id: number; price: number }[]>([]);
  const total = computed(() => items.value.reduce((s, i) => s + i.price, 0));
  function add(item: { id: number; price: number }) {
    items.value.push(item);
  }
  return { items, total, add }; // 回傳的才會被外部看到
});
```

元件裡 `const cart = useCartStore()` 就能用；若要解構成 ref，記得用 `storeToRefs(cart)`，否則會失去響應式。
