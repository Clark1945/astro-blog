### HTML

用來寫頁面的語言，我的結論是不必學。多看幾個網頁，就懂了。

```html
<!doctype html>
<html lang="zh-Hant">
  <head>
    <meta charset="utf-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1" />
    <title>頁面標題</title>
    <link rel="stylesheet" href="css/style.css" />
  </head>
  <body>
    <h1>標題</h1>
    <p>
      一段文字，裡面有<a href="https://developer.mozilla.org/zh-TW/">連結</a>。
    </p>
    <script defer src="js/app.js"></script>
  </body>
</html>
```

屬性：id、class、data-\*

```html
<article class="event major" id="tw-1895-cession" data-year="1895"></article>
```

- id：整頁唯一，用來定位，也是網址 #id 錨點。
- class：可以有多個、可以重複，用來套樣式與選取元素。

### CSS

HTML是骨架，CSS負責裝飾它。
引入方式有三種：

- 外部檔案（<link rel=>，建議）
- \<style>上面的區塊
- 元素上的 style="..."（只適合臨時除錯）。

同一個屬性被多條規則命中時，特異性高的贏：行內 style，大於 #id，大於 .class、屬性、偽類，大於標籤。同等級時，寫在後面的贏。!important 能蓋過一切，但會讓之後難以維護，盡量不用。

#### 非同步與瀏覽器 API

JS 在單一執行緒上跑，遇到網路請求、計時器這類要等的事，會交給瀏覽器處理，完成後再把回呼排進佇列，等目前的程式跑完才輪到它。所以等待時畫面不會卡住，但「誰先執行」要特別注意。

```javascript
<script>
console.log("1");
setTimeout(() => console.log("4"), 0);
Promise.resolve().then(() => console.log("3"));
console.log("2");
// 執行順序為 1 2 3 4
</script>
```

Promise and async/await

```javascript
async function loadJson(url) {
  const res = await fetch(url); // 等網路，但不卡畫面
  if (!res.ok) throw new Error("HTTP " + res.status); // fetch 遇到 404 不會自己丟錯
  return res.json(); // 也是 Promise
}

async function main() {
  try {
    const data = await loadJson("/data/taiwan.json");
    console.log(data.events.length);
  } catch (err) {
    console.error("載入失敗", err);
  }
}
main();
```

#### HTML 約束驗證(Constraint Validation)

| 屬性                              | 效果                                             | 注意事項                                                                          |
| --------------------------------- | ------------------------------------------------ | --------------------------------------------------------------------------------- |
| `required`                        | 不可留白，必填欄位。                             | 使用者若未輸入內容，表單無法送出。                                                |
| `type="email"`                    | 檢查是否符合 Email 格式。                        | 手機會顯示較適合輸入 Email 的鍵盤。                                               |
| `type="url"`                      | 檢查是否符合網址格式。                           | 通常需包含 `https://` 等協定。                                                    |
| `type="number"`                   | 只能輸入數值。                                   | 不適合電話、郵遞區號、身分證字號等資料，因為前導 `0` 可能消失。                   |
| `type="date"`                     | 提供日期選擇器並驗證日期格式。                   | 值會以標準日期格式處理。                                                          |
| `type="text" inputmode="numeric"` | 文字欄位，但手機顯示數字鍵盤。                   | 適合電話、郵遞區號、身分證字號等需要保留前導 `0` 的資料。                         |
| `pattern`                         | 使用正規表達式驗證輸入格式。                     | 必須整串符合（隱含 `^(?:…)$`）；僅適用於文字類型輸入；建議搭配 `title` 說明規則。 |
| `min` / `max` / `step`            | 設定數值、日期或範圍輸入的最小值、最大值與間隔。 | 主要用於 `number`、`date`、`range`。                                              |
| `minlength`                       | 設定最少輸入字數。                               | 常用於帳號、密碼等欄位。                                                          |
| `maxlength`                       | 設定最多輸入字數。                               | 超過限制時無法再輸入。                                                            |

- 前端驗證 vs 後端驗證：前端驗證是為了體驗（即時回饋、少一次往返）；後端驗證才是安全邊界，因為任何人都能用 curl 繞過前端。兩邊都要做。Spring Boot 用 @Valid 加 Bean Validation（@NotBlank、@Email、@Size），回 400 與欄位錯誤；前端把這些錯誤對應回欄位。兩處的規則會不同步，以後端為準。
- 避免重複提交：在 submit 事件裡停用送出鈕並用旗標擋住（Enter 與按鈕走同一條路）；後端也要冪等（idempotency key 或唯一鍵），因為使用者還能重新整理、連點、網路重試。
- 註冊、結帳、後台 CRUD 的表單，大部分規則（必填、格式、長度）用屬性就夠，複雜的跨欄位規則（確認密碼、起訖日期）才用 setCustomValidity。
- 送出前用 form.requestSubmit() 取代 form.submit()：前者會跑驗證並觸發 submit 事件，後者兩者都略過。

#### 資源載入

HTML 解析器是「邊下載、邊解析」的串流處理。遇到 <script> 時怎麼做，取決於它的屬性。選錯的後果從「頁面慢」到「querySelector 回傳 null」都有。
| 載入方式 | 下載 | 執行時機 | 多個腳本順序 | 能看到後面的 DOM | 適合用途 |
|----------|------|----------|--------------|------------------|----------|
| 普通 `<script>` | 立刻下載，暫停 HTML 解析 | 下載完立刻執行，解析被擋住 | 文件順序 | ❌ 不能 | 幾乎不該用 |
| `<script defer>` | 與解析並行 | HTML 解析完成後、`DOMContentLoaded` 前 | ✅ 文件順序 | ✅ 能 | 應用程式主程式碼 |
| `<script async>` | 與解析並行 | 下載完立刻執行，可能打斷解析 | ❌ 不保證 | ⚠️ 不一定 | 彼此獨立的腳本（統計、廣告） |
| `<script type="module">` | 並行（連同其 `import`） | 與 `defer` 相同 | ✅ 文件順序（加 `async` 則不保證） | ✅ 能 | 現代 JavaScript（`import` / `export`） |

#### 作用域與閉包

- 每次進入函式或區塊，引擎建立一個環境（Environment Record），其中有名稱與值，以及指向外層環境的連結。查找變數時沿著這條鏈往外找，找不到就是 ReferenceError。
- var：函式作用域，會提升（hoisting）且初始化為 undefined；let / const：區塊作用域，提升後處於暫時性死區（TDZ），宣告之前存取會丟 ReferenceError。const 只是不能重新賦值，物件內容仍可變。
- 閉包保存的是變數本身（參考），不是建立當下的值。所以多個函式可以共用同一份狀態；而 for (let i…) 之所以安全，是因為每一圈都有自己的新 i。
- 原始型別（number、string、boolean、null、undefined、symbol、bigint）賦值時複製值。
- 物件（包含陣列、函式、Date、Map）賦值時複製參考：兩個變數指向同一個物件。
- JS 的函式參數一律是「傳值」，但物件變數的「值」就是參考，這與 Java 傳物件參考的行為相同。
  | 做法 | 複製深度 | 注意事項 |
  |------|----------|----------|
  | `{...obj}` / `[...arr]` / `Object.assign()` | 淺層複製 | 只複製第一層；巢狀物件或陣列仍共用同一份參考。 |
  | `structuredClone(x)` | 深層複製 | 支援 `Date`、`Map`、`Set`、循環參考；不能複製函式、DOM 節點、Vue 的 `Proxy`（會拋出 `DataCloneError`）；`class` 實例會失去原型。 |
  | `JSON.parse(JSON.stringify(x))` | 深層複製（有損） | `Date` 會變字串；`undefined`、函式會消失；`NaN` 變成 `null`；循環參考會拋錯。 |

##### this、箭頭函式、call / apply / bind

- Java 的 this 永遠是當前物件。JS 的 this 是呼叫時決定的（箭頭函式例外）
- new Foo()：this 是新建立的物件。
- fn.call(obj, …) / fn.apply(obj, [args]) / fn.bind(obj)：this 就是 obj。call 立刻執行、參數逐一傳；apply 立刻執行、參數放陣列；bind 回傳新函式，this 永久綁定。
- obj.method()：this 是點號左邊的 obj。
- 單純的 fn()：嚴格模式（ES module、class 內）是 undefined，否則是全域物件。
- **箭頭函式：沒有自己的 this，用的是定義時外層的 this，call/bind 都改不了它。**

#### 事件迴圈（Event Loop）

- JS 引擎一次只執行一段程式（單執行緒），但瀏覽器在旁邊提供計時器、網路、使用者事件等能力。
- 事件迴圈是把「完成的工作」排隊送回主執行緒、一個一個執行的調度器。

1. Call stack──執行目前這個 task 的同步程式，直到堆疊清空
2. Microtasks──Promise.then、await 之後、queueMicrotask、MutationObserver。全部清空才繼續（包含執行中新加入的）
3. Render──需要時：樣式計算、排版、繪製；requestAnimationFrame 在繪製前執行
4. Next task──從 task queue 取下一個：setTimeout／setInterval 回呼、DOM 事件、postMessage、網路完成

- 所以 setTimeout(fn, 0) 不是「立刻」：它是「至少等這一輪的 microtask 與（可能的）渲染做完，再排進下一個 task」，而且瀏覽器有最小延遲，巢狀超過 5 層會被拉到至少 4ms；背景分頁的計時器還會被降頻到約 1 秒一次。
- 長任務會凍結頁面：同步的迴圈佔著 call stack，期間沒有事件處理、沒有渲染，使用者看到卡死。超過 50ms 就算 long task。解法是拆片（讓出主執行緒）、移到 Web Worker，或換演算法。
- Microtask 餓死：microtask 會一直清到空，如果每個 microtask 又排一個新的 microtask，task 與渲染永遠輪不到。
- async/await：await x 之前的程式同步執行；之後的程式變成 microtask，等 x 完成才排進去。async 函式永遠回傳 Promise

#### Promise 深入：狀態、串接、並行與錯誤傳遞

- Promise 代表「一個尚未知道、將來會有結果的值」。三種狀態：pending（等待）→ fulfilled（成功）或 rejected（失敗）
- .then(onOk, onErr) 永遠回傳新的 Promise。回呼 return 的值成為新 Promise 的結果（若是 Promise 就會被吸收）；回呼 throw 則讓新 Promise rejected。
- 錯誤傳遞：rejection 會沿著鏈往下找最近的 catch／onErr，途中的 then(onOk) 全部被略過；catch 處理完並正常回傳後，鏈就「恢復」成 fulfilled。想讓錯誤繼續往下傳，要在 catch 裡重新 throw。
- Unhandled rejection: 一個 rejected Promise 在該輪結束時沒有人處理，瀏覽器會觸發 unhandledrejection 事件、Node 預設會讓行程終止。常見成因：忘了 await、忘了 return 內層 Promise、在 forEach 的 async callback 裡丟錯。

| 組合器                 | 何時完成                          | 失敗時                                                                           | 適合用途                   |
| ---------------------- | --------------------------------- | -------------------------------------------------------------------------------- | -------------------------- |
| `Promise.all()`        | 全部成功時                        | **快速失敗**：任一 Promise 失敗就立刻 `reject`（其他仍會繼續執行，但結果被忽略） | 多個任務互相依賴、缺一不可 |
| `Promise.allSettled()` | 全部落定（fulfilled 或 rejected） | 永不 `reject`；回傳每個結果的 `{ status, value \| reason }`                      | 批次作業、需要知道每筆結果 |
| `Promise.race()`       | 第一個落定（成功或失敗）          | 第一個若失敗就立即 `reject`                                                      | 逾時控制、搶最快回應       |
| `Promise.any()`        | 第一個成功時                      | 全部失敗才 `reject`，拋出 `AggregateError`                                       | 多個備援來源取最快成功結果 |

順序執行 vs 並行：在迴圈裡 await 每一個，就是一個做完才做下一個（總時間相加）。互不依賴的工作應該先同時啟動，再一起等：await Promise.all(items.map(fn))。但同時送出上千個請求會打爆伺服器或瀏覽器的連線數，要限制並行數量。

- try/catch 只攔得住同步丟出的錯，以及 await 的 Promise 的 rejection。沒有 await 的 Promise、setTimeout 回呼裡的錯，都逃出 try/catch。
- fetch 的 Promise 只在「網路層失敗」時 reject（斷線、DNS 失敗、被 CORS 擋下），HTTP 404／500 都是 fulfilled。你必須自己檢查 res.ok。這與 Axios 預設「非 2xx 就丟錯」不同，也與 Spring 的 RestTemplate 預設行為不同。
- Response: status, ok (200–299), headers; body 是串流，只能讀一次（res.json()、res.text() 擇一；要讀兩次用 res.clone()）。res.json() 本身也是 Promise，內容不是合法 JSON 會 reject 為 SyntaxError。
- AbortController: const ctrl = new AbortController(); fetch(url, { signal: ctrl.signal }); ctrl.abort()。被取消的 fetch 會 reject 成 AbortError（DOMException，e.name === "AbortError"），那是「正常取消」而不是錯誤，不要顯示錯誤訊息。一個 controller 用過就不能再用，每次請求建立新的。
- 逾時: fetch(url, { signal: AbortSignal.timeout(5000) }) 逾時時 reject 為 TimeoutError。要「手動取消 + 逾時」兩者並用：AbortSignal.any([ctrl.signal, AbortSignal.timeout(5000)])。fetch 預設沒有逾時，可能永遠等下去。
- CORS: 跨來源請求由瀏覽器強制檢查，伺服器沒回對的 Access-Control-Allow-Origin，fetch 就是 reject 成 TypeError: Failed to fetch，而且 JS 看不到原因。非「簡單請求」（例如帶 Authorization 或 JSON content-type）會先送 OPTIONS 預檢。解法在伺服器端（Spring：@CrossOrigin 或 CorsRegistry），不是前端。
- 競態條件（race condition）: 使用者輸入 "a" 再輸入 "ab"，兩個請求的回應順序不保證。若 "a" 的回應較慢、後到，就會蓋掉 "ab" 的結果，畫面顯示過期資料。解法：新請求出發時取消上一個（AbortController），或用請求序號只接受最新的。

### 面試常見考題

20 題選擇題，先自己想答案，再點「看答案」展開解析。程式碼都可以貼到瀏覽器 Console（F12）驗證。

#### 一、事件迴圈與 Promise

**Q1. 以下程式的輸出順序是？**

```javascript
console.log("1");
setTimeout(() => console.log("2"), 0);
Promise.resolve().then(() => console.log("3"));
queueMicrotask(() => console.log("4"));
console.log("5");
```

- (A) 1 2 3 4 5
- (B) 1 5 3 4 2
- (C) 1 5 2 3 4
- (D) 1 5 4 3 2

<details>
<summary>看答案</summary>

**(B) 1 5 3 4 2**

同步程式先跑完（1、5）。接著清空 microtask 佇列，`then` 與 `queueMicrotask` 進的是同一個佇列，先排先跑（3、4）。`setTimeout` 是下一個 task，最後才輪到（2）。

</details>

**Q2. 以下程式的輸出順序是？**

```javascript
async function f() {
  console.log("1");
  await null;
  console.log("2");
}
console.log("3");
f();
console.log("4");
```

- (A) 3 1 2 4
- (B) 3 4 1 2
- (C) 3 1 4 2
- (D) 1 2 3 4

<details>
<summary>看答案</summary>

**(C) 3 1 4 2**

呼叫 async 函式時，`await` 之前的程式是同步執行的，所以 1 緊接在 3 後面。`await` 之後的程式變成 microtask，要等目前的同步程式（印出 4）跑完才執行。

</details>

**Q3. 以下程式的輸出順序是？**

```javascript
new Promise(resolve => {
  console.log("x");
  resolve();
  console.log("y");
}).then(() => console.log("z"));
console.log("w");
```

- (A) x y w z
- (B) x z y w
- (C) w x y z
- (D) x w y z

<details>
<summary>看答案</summary>

**(A) x y w z**

`new Promise` 的 executor 是**同步**執行的，而且 `resolve()` 不會中斷它，所以 y 照樣印出。`then` 的回呼是 microtask，等同步的 w 印完才輪到 z。

</details>

**Q4. 兩條 Promise 鏈交錯時，輸出順序是？**

```javascript
Promise.resolve()
  .then(() => console.log("a1"))
  .then(() => console.log("a2"));
Promise.resolve()
  .then(() => console.log("b1"))
  .then(() => console.log("b2"));
```

- (A) a1 a2 b1 b2
- (B) a1 b1 a2 b2
- (C) b1 b2 a1 a2
- (D) 順序不固定

<details>
<summary>看答案</summary>

**(B) a1 b1 a2 b2**

每個 `.then` 要等上一個 Promise 完成，才會把下一個回呼排進 microtask 佇列。所以第一輪只有 a1、b1 在佇列裡，它們執行完才把 a2、b2 排進去。順序是固定的，不是隨機。

</details>

**Q5. 以下程式的輸出順序是？**

```javascript
setTimeout(() => {
  console.log("t1");
  Promise.resolve().then(() => console.log("p1"));
}, 0);
setTimeout(() => console.log("t2"), 0);
```

- (A) t1 t2 p1
- (B) p1 t1 t2
- (C) t1 p1 t2
- (D) t2 t1 p1

<details>
<summary>看答案</summary>

**(C) t1 p1 t2**

每個 task 執行完，事件迴圈都會先清空 microtask，才取下一個 task。t1 這個 task 裡排進的 p1，會在 t2 之前執行。

</details>

**Q6. 以下程式的輸出是？**

```javascript
Promise.reject(new Error("boom"))
  .then(() => console.log("A"))
  .catch(() => {
    console.log("B");
    return 1;
  })
  .then(v => console.log("C", v));
```

- (A) A B C 1
- (B) B
- (C) B C 1
- (D) B C undefined

<details>
<summary>看答案</summary>

**(C) B C 1**

rejection 會跳過途中的 `then(onOk)`，直接找到最近的 `catch`，所以 A 不會印。`catch` 正常 `return 1` 之後，鏈就恢復成 fulfilled，下一個 `then` 收到的值是 1。

</details>

**Q7. `p1` 100ms 後成功，`p2` 50ms 後失敗。`Promise.all([p1, p2])` 會？**

- (A) 100ms 後 fulfilled，結果是 `[p1 的值, undefined]`
- (B) 約 50ms 時 rejected，原因是 p2 的錯誤；p1 仍會繼續執行
- (C) 約 50ms 時 rejected，而且 p1 會被取消
- (D) 100ms 後 rejected

<details>
<summary>看答案</summary>

**(B)**

`Promise.all` 是快速失敗：任一個失敗就立刻 reject。但 Promise 沒有「取消」的機制，p1 會照樣跑完，只是結果被忽略。如果需要每一筆的結果（包含失敗的），要用 `Promise.allSettled`。

</details>

#### 二、作用域、提升與閉包

**Q8. 以下程式的輸出是？**

```javascript
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
```

- (A) 0 1 2
- (B) 3 3 3
- (C) 2 2 2
- (D) undefined ×3

<details>
<summary>看答案</summary>

**(B) 3 3 3**

`var` 是函式作用域，三個回呼共用同一個 `i`。閉包保存的是變數本身，不是當下的值；回呼執行時迴圈早就跑完，`i` 已經是 3。改成 `let` 就會印出 0 1 2，因為每一圈都有自己的新 `i`。

</details>

**Q9. 執行以下程式會發生什麼事？**

```javascript
console.log(a);
console.log(b);
var a = 1;
let b = 2;
```

- (A) 印出 1，再印出 2
- (B) 印出 undefined，再印出 undefined
- (C) 印出 undefined，然後拋出 ReferenceError
- (D) 第一行就拋出 ReferenceError

<details>
<summary>看答案</summary>

**(C)**

`var a` 會提升並初始化為 `undefined`，所以第一行印出 undefined。`let b` 也會提升，但宣告之前處於暫時性死區（TDZ），存取就拋出 ReferenceError。

</details>

**Q10. 以下哪一行會拋出錯誤？**

```javascript
const o = { n: 1 };
o.n = 2; // 第 2 行
o.m = 3; // 第 3 行
o = { n: 4 }; // 第 4 行
```

- (A) 第 2 行
- (B) 第 3 行
- (C) 第 4 行
- (D) 都不會

<details>
<summary>看答案</summary>

**(C) 第 4 行**，拋出 `TypeError: Assignment to constant variable.`

`const` 只限制「不能重新賦值」，物件內容照樣能改、能新增屬性。這跟 Java 的 `final` 參考是同一個概念。

</details>

#### 三、this 與 call / apply / bind

**Q11. 在嚴格模式下，以下程式的結果是？**

```javascript
"use strict";
const obj = {
  name: "obj",
  hi() {
    return this.name;
  },
};
const f = obj.hi;
console.log(obj.hi());
console.log(f());
```

- (A) obj、obj
- (B) obj、undefined
- (C) obj，然後拋出 TypeError
- (D) undefined、undefined

<details>
<summary>看答案</summary>

**(C)**

`this` 是呼叫時決定的。`obj.hi()` 點號左邊是 obj，所以 this 是 obj。把方法取出來單獨呼叫 `f()`，嚴格模式下 this 是 `undefined`，讀 `undefined.name` 就拋出 TypeError。把方法當回呼傳出去（例如 `button.addEventListener("click", obj.hi)`）時常踩到這個坑。

</details>

**Q12. 在 ES module 中，以下程式的輸出是？**

```javascript
const obj = {
  name: "obj",
  regular() {
    return this.name;
  },
  arrow: () => this,
};
console.log(obj.regular(), obj.arrow());
```

- (A) obj obj
- (B) obj undefined
- (C) obj window
- (D) undefined undefined

<details>
<summary>看答案</summary>

**(B) obj undefined**

箭頭函式沒有自己的 this，用的是**定義時**外層的 this。這裡外層是 module 的最上層，this 是 `undefined`。物件字面量的大括號不會產生新的 this，所以不要用箭頭函式當物件方法。

</details>

**Q13. 以下程式的輸出是？**

```javascript
function f() {
  return this.n;
}
const g = f.bind({ n: 1 });
console.log(g.call({ n: 2 }));
```

- (A) 1
- (B) 2
- (C) undefined
- (D) 拋出 TypeError

<details>
<summary>看答案</summary>

**(A) 1**

`bind` 回傳的新函式，this 被永久綁定，之後再用 `call`、`apply` 都改不了。

</details>

**Q14. 關於 call、apply、bind，哪個敘述正確？**

- (A) 三者都會立刻執行函式
- (B) `apply` 立刻執行，參數用陣列傳入
- (C) `bind` 立刻執行，並永久綁定 this
- (D) `call` 回傳新函式，參數逐一傳入

<details>
<summary>看答案</summary>

**(B)**

- `call`：立刻執行，參數逐一傳：`fn.call(obj, a, b)`
- `apply`：立刻執行，參數放陣列：`fn.apply(obj, [a, b])`
- `bind`：不執行，回傳 this 已綁定的新函式

</details>

#### 四、型別、比較與複製

**Q15. 以下哪個運算結果是 `true`？**

- (A) `NaN === NaN`
- (B) `null === undefined`
- (C) `"0" === 0`
- (D) `null == undefined`

<details>
<summary>看答案</summary>

**(D)**

`==` 會先做型別轉換，`null == undefined` 是語言規格特別定義的 true。`===` 不轉型別，所以 (B)(C) 都是 false。`NaN` 跟任何值都不相等，包括自己；判斷 NaN 要用 `Number.isNaN()`。

</details>

**Q16. 以下程式印出什麼？**

```javascript
const a = { x: 1, inner: { y: 1 } };
const b = { ...a };
b.x = 2;
b.inner.y = 2;
console.log(a.x, a.inner.y);
```

- (A) 1 1
- (B) 2 2
- (C) 1 2
- (D) 2 1

<details>
<summary>看答案</summary>

**(C) 1 2**

展開運算子是淺層複製：第一層的 `x` 被複製了，改 `b.x` 不影響 `a`；但 `inner` 複製的是參考，兩邊指向同一個物件。需要深層複製時用 `structuredClone(a)`。

</details>

**Q17. `JSON.parse(JSON.stringify({ d: new Date(0), u: undefined, n: NaN }))` 的結果是？**

- (A) `{ d: Date 物件, u: undefined, n: NaN }`
- (B) `{ d: "1970-01-01T00:00:00.000Z", n: null }`
- (C) `{ d: "1970-01-01T00:00:00.000Z", u: null, n: NaN }`
- (D) 拋出錯誤

<details>
<summary>看答案</summary>

**(B)**

JSON 深拷貝是有損的：`Date` 變成 ISO 字串、值為 `undefined` 的屬性直接消失、`NaN` 變成 `null`。

</details>

**Q18. 以下程式的結果是？**

```javascript
localStorage.setItem("user", { name: "Clark" });
console.log(localStorage.getItem("user"));
```

- (A) `{ name: "Clark" }`
- (B) `'{"name":"Clark"}'`
- (C) `"[object Object]"`
- (D) 拋出 TypeError

<details>
<summary>看答案</summary>

**(C) `"[object Object]"`**

localStorage 只能存字串，傳入物件會被 `String()` 轉成 `"[object Object]"`，而且不會報錯，資料就這樣悄悄壞掉。要存物件，先 `JSON.stringify`，讀出來再 `JSON.parse`。

</details>

#### 五、瀏覽器 API 與錯誤處理

**Q19. 以下程式的結果是？**

```javascript
try {
  setTimeout(() => {
    throw new Error("x");
  }, 0);
} catch (e) {
  console.log("caught");
}
```

- (A) 印出 caught
- (B) 什麼都不印，Console 出現 Uncaught Error: x
- (C) 什麼都不印，錯誤被默默吞掉
- (D) 印出 caught，然後出現 Uncaught Error

<details>
<summary>看答案</summary>

**(B)**

`try` 區塊只是「排了一個計時器」就結束了。回呼在之後另一個 task 執行時，原本的 try/catch 早已不在 call stack 上，攔不到它。要攔錯，得把 try/catch 寫在回呼裡面，或改用 Promise 加 `await`。

</details>

**Q20. `fetch("/api/not-found")` 收到 HTTP 404，會發生什麼事？**

- (A) Promise rejected，拋出 TypeError
- (B) Promise rejected，拋出 HTTP 404 錯誤
- (C) Promise fulfilled，`res.ok` 是 false，`res.status` 是 404
- (D) Promise 永遠 pending

<details>
<summary>看答案</summary>

**(C)**

fetch 只在網路層失敗（斷線、DNS 失敗、被 CORS 擋下）時才 reject。只要伺服器有回應，包括 404、500，都是 fulfilled，必須自己檢查 `res.ok`。這點跟 Axios 預設「非 2xx 就丟錯」不同。

</details>
